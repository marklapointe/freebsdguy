## 1. Goals

1. Ship a **sane, hardened** MDWeb (secrets, JWT, roles, uploads, structure, CI).
2. Provide a **first-class FreeBSD port** under `www/mdweb` that builds a **real package**, installs cleanly, and runs under `rc.d`.
3. Every meaningful change set is gated by a **full regression round** on the FreeBSD test system:
   - build port → package
   - install from package (clean or reinstall)
   - service start + smoke
   - API + Playwright UI inspections
   - deinstall / reinstall sanity when relevant
4. Document **every angle** an agent (or human) can use to test MDWeb so regressions cannot hide in one layer.

### Non-goals (this plan)

- Upstream FreeBSD ports commit review timeline (we produce a correct port skeleton + test it; submission PR is optional follow-up).
- Database migration off Markdown/JSON.
- Multi-tenant SaaS features.

## 3. Product hardening (recap of Phases 0–3)

Execute in order. Details match the previously approved design.

### Phase 0 — Hygiene
- Ignore/untrack `coverage/`
- Fix destructive `Makefile clean`
- Docs truth (password `admin`, no stale `ports/` claims until port is restored)
- Green local `npm ci && npm test && npm run build`

### Phase 1 — Security
- Public `GET /api/config` never returns `apiKey` / `jwtSecret`
- Production refuses default JWT
- Authenticated theme writes; admin-only global theme
- Role allowlist `admin|contributor` + `requireRole` middleware
- Multer size + MIME limits
- Do not HTML-sanitize raw Markdown body
- No API keys in query strings
- CORS configurable; Containerfile installs real prod deps

### Phase 2 — Structure
- Split `server/index.ts` into routes/middleware
- Split Admin UI out of `App.tsx`
- Prune unused npm packages
- Frontend `/admin` route guard

### Phase 3 — Correctness / DX
- Config path resolution for system install
- Real image pagination or remove fake UI
- `GET /api/health`
- CI workflow (GitHub Actions)
- Tighter production CSP
- Rate-limit docs or live reload of windows

**Every phase ends with a Regression Round (Section 6) once the FreeBSD port exists.**  
Until the port lands, use **dev mode regression** (Section 6.3) on the test host.

## 4. FreeBSD Ports Collection entry

### 4.1 Location and naming

| Item | Choice | Rationale |
|------|--------|-----------|
| Category | `www` | Web application |
| Port directory | `www/mdweb` | lowercase; FreeBSD convention (historical `MDWeb` was wrong case) |
| Package name | `mdweb` | Matches rc script `mdweb` |
| Install root | `${PREFIX}/www/mdweb` (`WWWDIR`) | Matches prior design `/usr/local/www/MDWeb` → normalize to `mdweb` |
| Config | `${PREFIX}/etc/mdweb/` | `config.json`, `users.json` samples |
| Data/posts | `${WWWDIR}/server/posts` or `/var/db/mdweb/posts` | Prefer `/var/db/mdweb` for writable data owned by `www` |
| RC | `USE_RC_SUBR=mdweb` | Existing `mdweb.rc` adapted to ports layout |
| Man | `share/man/man1/mdweb.1` | Already in tree |

Repo layout (in-project, for development and as source for ports PR):

```text
ports/www/mdweb/
  Makefile
  distinfo
  pkg-descr
  pkg-plist          # or auto-plist generation
  pkg-message        # first-run password / JWT instructions
  files/
    mdweb.in         # rc script template (ports style)
    patch-*          # if needed
```

Overlay install on test host for iterative work:

```sh
# Preferred: local overlay without polluting system ports permanently
sudo mkdir -p /usr/ports/www/mdweb
# rsync project ports/www/mdweb/ → /usr/ports/www/mdweb/
# Ensure www/Makefile lists SUBDIR += mdweb (or use make in the dir directly)
```

Direct `make -C /usr/ports/www/mdweb package` works without editing the category Makefile for local testing.

### 4.2 Official-ports network constraint

Poudriere / package builds **must not** hit the network after `fetch`.

**Chosen strategy (vendored npm cache), modeled on `www/evcc` / `www/opengist`:**

1. **Distfiles:**
   - Source: GitHub release tarball **or** `USE_GITHUB` tagged release `v${DISTVERSION}`
   - Offline npm cache: `mdweb-npm-cache-${DISTVERSION}.tar.zst` containing a populated npm cache or `node_modules` suitable for `npm ci --offline`

2. **Build:**
   - `USES=nodejs:lts,build` (or pin `nodejs:22,build` to match LTS on FreeBSD)
   - `BUILD_DEPENDS=npm${NODEJS_SUFFIX}>0:www/npm${NODEJS_SUFFIX}`
   - `do-build`: restore cache → `npm ci --offline` → `npm run build`
   - Runtime does **not** need Vite; needs Node + production `node_modules` (or prune to production)

3. **Install stage:**
   - Stage `dist/`, `server/` (lib + scripts, not tests), production `node_modules`, `package.json`, man page
   - Sample configs: `${ETCDIR}/config.json.sample`, `users.json.sample` with **no** weak default in production path; `pkg-message` tells admin to run `mdweb-setup` / set password
   - `WWWDIR` owned appropriately; writable dirs via `@dir` and `www:www` where needed
   - Do **not** ship `coverage/`, `tests/`, `.git`, agent planning docs into the package

4. **Run:**
   - `USES=nodejs:lts,run` (or combined build+run)
   - RC runs as `www`, sets `NODE_ENV=production`, `CONFIG_DIR=/usr/local/etc/mdweb`, `JWT_SECRET` from `/usr/local/etc/mdweb.env` or `rc.conf`
   - Binary/wrapper: `${PREFIX}/bin/mdweb` → `exec tsx` **or** preferably compile/start via `node` on compiled JS

**Important production note:** Running TypeScript via `tsx` in production pulls a large toolchain. Port design should prefer:

- **Preferred:** emit JS for server (`tsc` server build or `tsx` only at build) and run `node server/index.js`
- **Acceptable interim:** depend on `tsx` as runtime dep (document cost)

Phase 3 should add a proper server compile path if missing.

### 4.3 Historical port lessons

Git history (`09a1109` … removed in `20edfc2`) had `ports/www/MDWeb` that:

- Ran `npm install` during `do-build` (network during build — **breaks poudriere**)
- Copied entire `node_modules` including devDeps
- Used uppercase path `MDWeb`
- Placeholder `distinfo` / incomplete plist early on

**Do not restore that Makefile as-is.** Reimplement with offline cache + production prune + correct naming.

### 4.4 Port Makefile sketch (target shape)

```make
PORTNAME=	mdweb
DISTVERSION=	1.0.0
CATEGORIES=	www
MASTER_SITES=	GH LOCAL/${MAINTAINER:C/@.*//}/${PORTNAME}/:npmcache
# adjust MASTER_SITES once release + cache hosting is decided

MAINTAINER=	mark@cloudbsd.org
COMMENT=	Markdown personal website with React frontend and Express API
WWW=		https://github.com/marklapointe/freebsdguy

LICENSE=	MIT
LICENSE_FILE=	${WRKSRC}/LICENSE

BUILD_DEPENDS=	npm${NODEJS_SUFFIX}>0:www/npm${NODEJS_SUFFIX}
RUN_DEPENDS=	# node from USES=

USES=		nodejs:22,build,run
USE_GITHUB=	yes
GH_ACCOUNT=	marklapointe
GH_PROJECT=	freebsdguy
# GH_TAGNAME when releases exist

USE_RC_SUBR=	mdweb
NO_ARCH=	yes

# Offline npm cache distfile (regenerate via maintainer target)
DISTFILES+=	${PORTNAME}-npm-cache-${DISTVERSION}${EXTRACT_SUFX}:npmcache

# Users/groups: run as www
# SUB_LIST for paths in rc script

do-build:
	cd ${WRKSRC} && ${SETENV} ${MAKE_ENV} npm ci --offline --omit=dev
	cd ${WRKSRC} && ${SETENV} ${MAKE_ENV} npm run build
	# optional: compile server TS → JS

do-install:
	# stage WWWDIR, ETCDIR samples, man, bin wrapper

.include <bsd.port.mk>
```

Maintainer helper: `make regenerate-npm-cache` (document in `ports/www/mdweb/README` or pkg-descr comments).

### 4.5 Port QA checklist (each regression round)

From Porter’s Handbook recommended order:

1. `make clean`
2. `make stage`
3. `make stage-qa`
4. `make package` (as non-root when possible)
5. `portlint -A` / `portclippy` if available
6. `pkg install -y ./work/pkg/mdweb-*.pkg` (or `make install`)
7. Configure JWT + admin password; `service mdweb start`
8. Smoke + Playwright + API suite
9. `make deinstall` / `pkg delete mdweb`
10. Optional: poudriere testport when poudriere jails are configured

## 5. Packaging and install layout (runtime contract)

| Path | Purpose | Owner |
|------|---------|--------|
| `/usr/local/www/mdweb/` | App (dist + server + prod modules) | root:wheel, read-only for www |
| `/usr/local/etc/mdweb/config.json` | Site config | root or www, mode 0640 |
| `/usr/local/etc/mdweb/users.json` | Users | www, mode 0600 |
| `/usr/local/etc/mdweb.env` | `JWT_SECRET`, optional AI keys | root, mode 0600 |
| `/var/db/mdweb/posts/` | Markdown posts + images | www:www |
| `/var/db/mdweb/themes/` | Theme JSON | www:www |
| `/var/run/mdweb.pid` | PID | www |
| `/usr/local/etc/rc.d/mdweb` | Service | root |
| `/usr/local/bin/mdweb` | Start helper (optional) | root |

App must honor:

- `CONFIG_DIR` / `CONFIG_PATH` / `USERS_PATH`
- `JWT_SECRET` from environment (required in production)
- `PORT` or `mdweb_port` from rc
- Relative `postsDir` resolved safely for system install (Phase 3 path fix)

First-boot:

1. Copy samples if missing  
2. Refuse start without strong `JWT_SECRET`  
3. `pkg-message` + `npm run setup` / `mdweb-change-password` equivalent installed as scripts

## 7. Playwright and multi-angle testing research

### 7.1 Why multiple angles

| Layer | Catches |
|-------|---------|
| Unit/integration (Vitest) | Logic, pure API contracts, filesystem helpers |
| Package/port build | Missing files, wrong plist, offline npm, FreeBSD path bugs |
| Service/rc | User, env, pid, restart, permissions |
| HTTP API (curl/supertest) | Authz, secrets leak, status codes |
| Playwright UI | Broken client routes, login, admin, markdown, themes, uploads |
| Static security checks | Dependency audit, secret scan, CSP headers |
| Observability | Logs, health, process identity |

No single layer is enough. **Package install + Playwright** is the minimum “real FreeBSD user” bar.

### 7.2 Playwright strategy (recommended)

**Runner location:** Agent workstation (Linux + Google Chrome).  
**SUT location:** FreeBSD host service.

```bash
# On agent
export MDWEB_BASE_URL=http://172.16.176.133:5173
export MDWEB_ADMIN_USER=admin
export MDWEB_ADMIN_PASS=...   # from test bootstrap, never commit
npx playwright test
```

**Do not** rely on FreeBSD Chromium packages (not available as a real browser in pkg search). Firefox on FreeBSD is possible later but slower to automate from this agent.

**Suite outline** (`e2e/`):

| Spec | Coverage |
|------|----------|
| `public-home.spec.ts` | Home loads, site name, post list, theme CSS vars present |
| `public-post.spec.ts` | Open post, markdown render, catalog if present |
| `search.spec.ts` | Search works when enabled; 403/disabled when toggle on |
| `login.spec.ts` | Bad password fails; good password lands with token |
| `admin-posts.spec.ts` | Create / edit / pin / delete post |
| `admin-images.spec.ts` | Upload image, appear in manager, delete, bulk delete |
| `admin-security.spec.ts` | Settings save; public config never shows raw API key in network tab |
| `theme.spec.ts` | Switch light/dark; unauth cannot poison global theme (API assert) |
| `a11y-smoke.spec.ts` | Optional axe on home/login |
| `visual-smoke.spec.ts` | Screenshot home + post (threshold) |

**Auth helper:** API login → inject `localStorage` token before UI admin tests (faster, stable).  
Also keep one full UI login path test.

**Network assertions:** Playwright `page.on('response')` to ensure `/api/config` body has no `apiKey` with length > 0 secret material.

### 7.5 What “full inspections using Playwright” means here

Not a single screenshot. Each round must:

1. Exercise **anonymous** and **authenticated** journeys  
2. Assert **network** responses for secret leakage  
3. Cover **CRUD** for posts and images  
4. Capture **failure artifacts** (trace, screenshot, video on fail)  
5. Be **rerunnable** against package-installed service (not only `vite dev`)

## 10. Risks

| Risk | Mitigation |
|------|------------|
| Offline npm cache huge | Prune devDependencies; zstd; document regenerate |
| sharp native module on FreeBSD | Build `sharp` on FreeBSD during port build; test install |
| Playwright only from Linux | Document BASE_URL; do not require browser on FreeBSD |
| Port naming vs old MDWeb | Use `mdweb`; update all paths |
| Passwordless sudo scripts | Keep scripts explicit; never embed secrets in repo |
| FreeBSD 16-CURRENT drift | Pin node 22; re-run regression after host updates |
