# 4.3 MDWeb Testing Gaps — What We Must Cover

**Policy:** Every meaningful change is gated by a **full regression round**:
1. `npm test` (unit/integration)
2. `npm run build`
3. FreeBSD package path when packaging changed (`scripts/freebsd-package-round.sh` or smoke on live install)
4. **Full Playwright suite** against the live deploy (`MDWEB_BASE_URL=… npx playwright test`)
5. Playwright must assert **console/network health** (no CSP CDN failures, no silent 429 masking as “invalid credentials”)

Shallow checks (health-only, “nav exists”) are **not** enough. Login failures caused by rate limits proved that.

## 3. Recommended Playwright suite layout

```
e2e/
  00-health-console.spec.ts   # health + no CDN + no fatal console
  01-public.spec.ts           # home, post detail, search
  02-auth.spec.ts             # login fail/success/logout/rate-limit message
  03-posts-crud.spec.ts       # create edit pin delete
  04-images.spec.ts           # upload list delete bulk
  05-admin-settings.spec.ts   # site name, theme, security toggles
  06-security.spec.ts         # secrets, unauth mutations
```

**Global setup:**
- Restart or reset rate-limit state on SUT when possible
- Or skip API limiter in `E2E=1` / higher limits on test host config
- `storageState` for authenticated admin after login once

**Hard fail conditions:**
- Console error matching `/CSP|unpkg|Failed to load resource.*unpkg/`
- Unexpected 429 on first login attempt of suite
- Page white with empty `#root` after networkidle

## 5. Definition of “full regression” (mandatory)

```bash
# 1 local
npm test && npm run build

# 2 deploy target (FreeBSD or local prod)
export MDWEB_BASE_URL=http://172.16.176.133:5173
export MDWEB_ADMIN_USER=admin
export MDWEB_ADMIN_PASS=admin

# 3 API smoke
./scripts/api-smoke.sh

# 4 FULL Playwright (not a subset)
npx playwright test

# 5 if packaging changed
./scripts/freebsd-package-round.sh   # then re-run 3+4
```

CI (GitHub Actions): unit + build always. Full Playwright against FreeBSD is host-gated (self-hosted runner or manual job).

## 7. What “check everything” means in practice

For each user-visible surface, at least one automated path that:
- Exercises the UI the human uses (Playwright), not only `supertest`
- Asserts success **and** failure modes
- Fails on network/CSP regressions
- Is re-run after every deploy to FreeBSD
