# MDWeb Testing Strategy

## Overview
This document outlines the testing strategy for MDWeb, ensuring both the Express backend and React frontend are reliable and maintainable.

## Goals
- Reach at least 80% code coverage for core logic (server/lib and key frontend components).
- Ensure all API endpoints are validated for security and correctness.
- Maintain a stable user experience through automated frontend testing.

## Backend Testing
- **Framework**: Vitest
- **Tools**: `supertest` for endpoint testing, `vi` for mocking.
- **Focus Areas**:
  - `server/lib/auth.ts`: Authentication and authorization logic.
  - `server/lib/posts.ts`: Markdown file management and metadata extraction.
  - `server/lib/ai-service.ts`: Integration with Ollama/OpenAI (mocked).
  - `server/lib/images.ts`: Image metadata manifest and deduplication logic.
  - `server/index.ts`: API route handling and middleware.

## Frontend Testing
- **Framework**: Vitest
- **Tools**: `@testing-library/react`, `jsdom`.
- **Focus Areas**:
  - `src/App.tsx`: Routing, post listing, and post viewing.
  - `Image Manager`: Drag-and-drop uploads, pagination, and conflict resolution prompts.
  - `Home` Component: Pagination/Load More functionality.
  - `Login` Component: Form submission and error handling.

## CI/CD Integration
- Tests should be run automatically on every push (if CI is configured).
- `npm test` is the primary entry point for running all tests.

## Mocks and Isolation
- Use `vi.mock` to isolate components from external dependencies (e.g., `axios`, `fs`).
- Ensure tests do not modify production data; use temporary directories for file system tests.
